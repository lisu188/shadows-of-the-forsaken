## Opt-in performance evidence

`PlayerValidationEvidence` remains disabled unless `SHADOWS_PLAYER_EVIDENCE_DIR` names an absolute local directory. It observes session state; it never sends input, advances time, changes frame caps/quality, resets the game or mutates progression. Existing snapshot retry, local-path restrictions and 10,000-event budget remain in place.

The observer adds hardware and performance/memory fields to the rolling `status.json`, plus at most **256 lifecycle records** in `performance.jsonl`. The rolling snapshot exposes the written count and whether that summary limit has been reached. Records retain the original session identifier on defeat, completion and reset, then start fresh counters for the new token. Normal-exit and observer-disable records retain the current session. These can be multiple checkpoints for the same session; do not sum them as separate runs. A summary includes display configuration and the complete fixed histogram; the frequent rolling snapshot omits the bin array.

Frame measurement is the actual realtime interval between observer `LateUpdate` calls. Eligibility requires both interval boundaries to be focused, unpaused, Running, with positive `Time.timeScale`; callbacks invalidate the baseline across suspension. Transition, focus, pause and non-running frames have separate exclusion counts. A baseline invalidated across suspension has unknown duration, recorded as zero rather than attributing the background gap to gameplay. Lifecycle summaries include observations completed before that callback, not a fabricated final frame.

The first **five eligible seconds per session** are warmup. An interval beginning before warmup finishes is excluded in full, and its duration/count remain reported. Every subsequent eligible interval is retained, including long frames: exact count, total, mean and maximum; quarter-millisecond histogram buckets through 512 ms plus one overflow bucket. Approximate p95 is the selected bucket's upper bound; if it falls in overflow, the observed maximum supplies a conservative upper bound. No outlier is capped, dropped or replaced. An empty sample cannot pass the frame budget. Exclusions make clear how much of the session was measured.

**Provisional implementation target:** a 60 FPS intent at 1280×720, with both mean and conservative approximate p95 frame intervals at or below 33.3 ms. This tolerance is not a sustained-60-FPS guarantee and is not a number specified by the DOCX. The report records resolution, fullscreen mode, quality index, VSync and requested frame-rate setting without changing them. Resolution mismatch, editor execution, missing samples or incomplete route coverage prevent treating the counters alone as final player qualification.

Hardware fields identify Unity/platform/editor status, operating system, CPU type/count/frequency, system memory, GPU/vendor/API and reported graphics memory. No user/device identifier is collected. `GC.GetTotalMemory(false)` is a managed-memory estimate without forced collection. Unity Profiler allocator used/reserved/unused values describe Unity's internal pools and may return zero when unavailable. They are **not** complete native/process working-set or GPU-use measurements and are not combined into a fictitious total. Sampled peaks may miss short spikes. Memory is reported without an arbitrary pass threshold.

These frame intervals include application scheduling, presentation pacing and the observer's own overhead; they are not CPU/GPU benchmark timings or a Unity Profiler capture. A hardware-specific report must still identify costly rooms/effects, investigate demonstrated problems, and repeat relevant routes after optimization. Actual standalone measurements remain **pending/deferred**, not supplied by writing instrumentation or passing accumulator tests.
