The [tracked interactive recorder](../../tools/Record-ForsakenPlaytest.ps1) now holds a temporary system/display execution request for its owned player lifetime and restores prior flags on the same dedicated thread in `finally`. It verifies caller/child token integrity, freezes the recorder and identity verifier in each kit, requires a final matching-session normal-exit event, rejects FMOD/native-fatal diagnostics even with exit code 0, and refuses empty declarations instead of looping on closed input. A separate review found and fixed a dump-only false-success path: the recorder now checks confined crash output after exit and again after declarations, before creating `run.json`. Unreadable or linked crash entries also fail qualification. It preserves failed/partial evidence. The original October 9 recorder and both prior October 14 versions remain retained. The [Microsoft execution-state reference](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate) defines the scope: this request does not prevent explicit user sleep/lock or device removal. No power plan, default audio device or driver was changed.

The [new hidden native validator](../../tools/native_player_validation.py) keeps audio and D3D11 enabled, verifies the frozen player before/after, records actual token integrity and graphics threading, and requires advancing same-session startup observations. It scans the player log plus launcher stdout/stderr, inventories requested crash output, and rejects fatal/audio/dump evidence, forced closure, incomplete observation or failed wake-request restoration. Normal closure targets only windows still owned by its spawned process. It never sends gameplay input or activates another app.

Early strict trials exposed a launch issue: Unity's **invisible** `Unity.BatchModeWindow` became the foreground window. These trials were stopped and retained as failures; no audio/native fatal marker appeared. Unity's [documented delayed-parent launch](https://docs.unity3d.com/6000.6/Documentation/Manual/UnityasaLibrary-Windows.html) produced a successful two-minute default-threading trial, but the ClientWorkerJobs comparison still hit the foreground guard. A hidden parent was also ignored in batch mode. Foreground and visibility checks were not relaxed.

The explicit `--player-mode embedded --parent-mode owned` path omits batch mode and runs the normal renderer in an invisible, nonactivating runner-owned window. A live read-only `GetParent` query verified the game's actual `UnityWndClass` child and its 1280×720 rectangle under that host; both were invisible and outside the foreground. The observed graphics mode was **ClientWorkerJobs**, matching the earlier failed attempt. The [first embedded trial](../../artifacts/goal-20261014/native-embedded-legacy/execution.json) observed fresh same-session startup state for 120 seconds, then exited normally with code 0, unchanged player identity, no fatal/audio diagnostic or crash artifact, restored wake request and verified host destruction. Its [live window-parent evidence](../../artifacts/goal-20261014/native-embedded-legacy/window-parent-observation.json) is separate from merely requesting a launch flag. Default batch/delayed behavior remains available; the recommended hidden normal-renderer command is in the playtest guide.

The [second embedded trial](../../artifacts/goal-20261014/native-embedded-legacy-repeat/execution.json) independently repeated that 120-second observation and normal shutdown with the same successful integrity/audio/crash/window/cleanup checks. Three strict two-minute lifecycle checks therefore passed: default batch rendering and two normal-renderer embedded ClientWorkerJobs trials. Four early strict trials failed the foreground constraint and remain failures; none contained FMOD/native fatal evidence. The earlier short baseline used the older observer and is separate from these stricter qualifications. The normal-renderer repeats reduce the graphics-threading difference from d272, but do not reproduce its 55-minute duration or explicit lock/remote/power transitions.

The [native diagnostic audit](../../artifacts/goal-20261014/native-diagnostics.json) found no matching Windows Application Error/WER/.NET event or player dump for the earlier failure. The earlier player explicitly logged low integrity. Current qualified native trials record medium integrity, RID 8192.
